REDO V2 METHOD FIX

Why V1 was stopped
------------------
The original experiment.py generated a fresh LLM proposal independently for every
policy/fault cell. Therefore a trial labelled with an injected transient fault could
fail before that transient fault was ever injected because the model naturally
generated malformed or multiple tool calls. This confounded natural generation
reliability with controlled recovery ability.

V2 design
---------
1. No-fault rows remain genuine end-to-end LLM runs.
2. Before injected-fault experiments, the model generates a clean tool-call chain.
   The chain must parse, pass schema/semantic validation, execute through MCP, and
   satisfy the independent task criterion.
3. The same validated LLM-generated proposal is then used as the common starting
   point for controlled fault injection.
4. Naive retry replays the identical failed proposal.
5. Closed-loop GVEF may regenerate after structured feedback.
6. A one-shot transient failure must therefore be recoverable by naive retry, while
   a persistent corrupted call remains corrupted when blindly replayed.
7. New results are written only to redo_v2_* folders. The interrupted V1 results are
   left untouched.
